# Governed execution and process evidence

Revision: r8 (proposed; Workspace v0.1-r4 direct boundary accepted). Provider: Execution. Direct providers: Assistance supplies consumed active binding use plus observed host state; Workspace supplies controlled Git intent and worktree authority; Application supplies config/store mechanics only. Direct consumers: Workspace consumes raw Git execution results; Intelligence consumes owned protocol/process leases after profile admission; Application persists Execution-owned records. Changes composes Workspace raw Git results and does not directly spawn. Vocabulary: [common](common.md).

## Host-state and spawn gate

Execution accepts a physical-effect request only with a consumed peer-validated active binding use, correlated observed host state, full Workspace worktree ID/incarnation/root/epoch after authority exists, controlled command, immutable local policy, and an Execution-minted profile permit. Assistance creates the binding generation only after its real D01 proof; an absent, bare, stale, or heuristic binding is `unavailable`, never a candidate for admission. Workspace constructs and validates raw Git argv. Intelligence chooses provider topology and a declared profile, then consumes an owned protocol lease. Neither model text nor an MCP field supplies an executable, argv, cwd, environment, or profile to Execution directly.

An active use is consumed once to admit/validate a request and must be freshly consumed again immediately before an owned child starts. A queued request retains only its immutable binding generation; a stop between queue and dequeue makes its later spawn refuse. A locally admitted child may finish after stop, but a stopped binding never by itself authorizes backend termination. Workspace sends the scoped `AuthorityRevoked { worktree_ref, old_epoch, reason }` path to Intelligence, which fences/releases its logical view and asks Execution to reap only an owned unshared process; shared peer cleanup remains explicit uncertainty.

The only accepted managed macOS/Linux replay input is the complete opaque JSON value from `_meta["codex/sandbox-state-meta"]`, and only when server initialization advertised the same experimental capability. Execution validates its supported managed value and invokes `codex sandbox --sandbox-state-json <one JSON argv value> -- <controlled child argv>` without shell interpolation. It preserves every JSON field/value, including unknown nested fields, and preserves `sandboxCwd` and special-path semantics; it does not expand project roots or add `--sandbox-state-readable-root`. `external`, proxy, multi-root, missing, malformed, or unknown states are unavailable. Execution owns the catalog of tested profile template/version pairs and mints a permit only for a supported class and effective permission/trust value. For template and semantic-state identities only, it replaces the parsed `sandboxCwd` and the prefix of ordinary path entries equal to or beneath that cwd with one stable workspace placeholder, retaining each relative suffix. Sibling/outside roots, special entries, access flags, network policy, and unknown fields remain significant and unchanged; the full raw state used for execution is never rewritten. Its per-invocation full-state digest is correlation evidence, not a fixture-root authorization boundary. Application may persist profile evidence but does not verify or issue permits. `disabled` is executable only after the host explicitly supplied that type, Execution accepted its host-case template, and local policy explicitly accepts the no-outer-sandbox case.

The API and its substitute checks are contract-ready. They are not D03 acceptance: a managed provider, check, or write remains unavailable until Assistance supplies the captured state from a D01-validated invocation and Execution records a real macOS Seatbelt result for the applicable template. v0.1 does not expose check-profile execution; Changes does not gain a spawn path by composing a raw Git result.

**Profile shape v2 (T35B).** Beyond the legacy digest, Execution derives a closed, versioned semantic shape `ProfileShapeV2` from a managed restricted sandbox state and admits a live state only when one accepted template proves it a *narrower authority* (`live ⊑ accepted`). The shape is conservative and deliberately incomplete: it is sound, not complete, and every unsupported thing is refused rather than approximated. The shape fields are the exact mechanism boolean `useLegacyLandlock` — a non-null `codexLinuxSandboxExe` refuses v2 derivation entirely, because the accepted helper string is evidence of a path, not a pin on the executable's identity, and no helper measurement exists in this build — the network mode (only `restricted` and `enabled` are recognized), preserved `glob_scan_max_depth` (absent versus present and its exact value are significant), non-deny rules keyed by tagged selectors, and required deny rules. Selectors are tagged, never placeholder strings: `WorkspaceRelative(components)` for the state's own validated sandbox cwd and component descendants, `Absolute(components)` for outside paths (exact, with no cache/home/policy buckets), and the distinct special selectors `Root`, `SlashTmp`, `Tmpdir`, which are never collapsed or inferred equivalent. Path denies and `glob_pattern` denies are distinct rule identities: a wildcard-free glob is never collapsed into a path deny, the canonical form always carries the glob tag, its base selector, and the byte-exact pattern remainder, and a backslash keeps literal path meaning versus glob-escape meaning, so a path deny and a same-text glob deny never share one digest. Entry paths and the RAW `sandboxCwd` string must satisfy a strict local grammar — an absolute local path or a `file://` local URI — validated before any URI conversion, and `..`, embedded `.`, relative paths, NUL bytes, empty components, URI host parts, percent-encoding, and query or fragment suffixes are rejected on the raw components before any normalization; containment is component-wise (a `/work-escape` sibling is never inside `/work`), and case or Unicode spellings are never folded. The portable cwd-derived authority is bound at derivation to the trusted candidate or Workspace worktree the operation actually touches: a state whose `sandboxCwd` is not component-wise that directory refuses derivation, as does any state whose cwd subtree overlaps an absolute restriction unprovably — a relocated cwd sitting inside an absolute path deny's subtree is the reviewed relocation attack and refuses outright (an absolute *grant* containing the cwd, and the captured credential-glob denies whose literal base contains the cwd, are the portability cases the accepted captures themselves carry and do not refuse). Unknown top-level, permission-profile, filesystem, entry, or selector fields, unknown access/network/special/missing-path values, `missing_path_behavior` on a deny, a `/` sandbox cwd, and a selector carrying two conflicting accesses all produce a typed `UnsupportedShape` and never a partial shape. Identical duplicate rules deduplicate; order never matters.

Narrowing (`prove_narrower`) is proven only by exactly seven sufficient conditions: (1) the same supported mechanism and selector vocabulary and filesystem type; (2) the same normalized set of non-deny selectors; (3) at each selector the live access is equal or reduced from write to read with `missing_path_behavior` unchanged; (4) every normalized accepted deny rule occurs in live; (5) additional live deny rules have recognized, verified narrowing semantics (only path denies and exact `glob_pattern` denies are recognized, with bases split at the literal prefix and pattern remainders preserved byte-for-byte, so no glob containment is ever computed); (6) network is equal or reduced from enabled to restricted; (7) glob expansion settings match exactly. Everything else refuses: removing a write selector, removing a nested read restriction such as a `.git` skip-read, adding any positive selector (which could reopen a denied subtree), weakening or forgetting an accepted deny, or changing the mechanism. A digest establishes equality and can never establish subset containment, so narrowing is always proven structurally, never by hash comparison. Admission also confers no native-read, cached-result, or trampoline authority: `validate_workspace_read` requires an independent read proof of the live state — the deny-free whole-root grant for whole-tree scope, or the conservative per-path read proof (T36B) for an explicitly named path — for every managed state, cwd matching or not, so an unproven path or tree stays unavailable for native reads and cached delivery.

For TypeScript support, Execution accepts only the exclusive per-worktree lease chosen by [TYPESCRIPT-r3](intelligence-v0.2.md). Its controlled command is the accepted Node executable followed by the immutable bridge invocation `typescript-language-server --stdio`; the accepted `tsserver.path` and every closure member are re-measured immediately before spawn. No ambient `PATH`, npm, plugin, network, syntax-server, or automatic-typing-acquisition input is admitted. Runtime descendant evidence remains `Unverified`; support instead depends on separate release-pinned Codex and Claude normal-shutdown acceptance records for the exact immutable bundle.

## Durable profile catalog and provider leases

Application persists opaque record bytes only. Execution accepts a restored profile record only when it exactly matches an Execution-owned expected D03 evidence record from trusted configuration/evidence, and its semantic complete-state identity matches the current observed state. The expected record includes stable profile identity/revision plus provider-binary, toolchain, configuration, trust, transport, permission-value, and immutable D03-evidence identities. Unknown, corrupt, extra, missing, duplicate-digest, revision-zero, or value-mismatched records are unavailable. A matching name or permission shape never restores a permit, and Application cannot mint one. The catalog holds at most eight accepted profiles, and a template's identity is its profile digest, so several accepted profiles may cover one host profile class (T25B): a read-only and a workspace-write Codex sandbox can both be accepted.

Records are versioned by `shape_version` (T35B). An absent field is the legacy v1 layout: its eleven-field closed layout, digest algorithms, and exact-match admission are unchanged byte-for-byte, and it is never silently upgraded or reinterpreted. Only the value `2` adds the field: a v2 record stores the domain-separated profile-shape digest (`BLAKE3("agent-ide/profile-shape/v2\0" || canonical)`) in `permission_value` and the separately domain-separated canonical digest of the complete captured state, cwd included, in `semantic_state`; the stored `sandbox_state` reconstructs the shape, so no duplicate shape object is persisted. Restoration is exact evidence matching — a v2 record matches only its own capture, never a narrower live state; subtyping is applied only later, between the accepted capture and a live state, inside `permit`. An explicit `shape_version: 1` (a mixed layout), any other version value, an unknown record key, or a missing key fails closed in Execution's version-aware record parser, which the launcher delegates to instead of pinning a field count. A template's identity is domain-separated per generation, so v1 and v2 templates never collide or cross-compare.

`permit` matches one complete template and never combines grants from multiple templates. The decision is ordered and fail-closed: no template for the class is `no_profile_for_class`; an exact v2 shape match is preferred; otherwise a v1 template whose legacy digest equals the live state's keeps its unchanged exact-digest admission; otherwise a v2 template proving the live shape a narrower authority admits, selected deterministically by template identity; and no passing candidate refuses with the most specific closed reason — `shape_unsupported:<class>` when the live state derives no v2 shape, `shape_not_narrower:<class>` when every v2 template fails the proof, and the legacy `profile_digest_mismatch:<class>` when the class holds only v1 templates whose digests all differ. Unsupported semantics never fall back to a looser comparison, and the permit keeps the live raw-state correlation digest as evidence of *which* exact state ran.

Execution's `ProviderLeaseRegistry` has finite total and per-backend view ceilings and uses the central `AdmissionController` only for a new owned physical backend. Pending requests count against both view ceilings before promotion. Compatible shared views retain one heavy-process reservation and count separately as forwarders. An exclusive backend accepts one view. A new owned backend exposes its reservation only as a one-time view-bound spawn capability consumed by Execution's protocol-child setup; shared reuse, borrowed endpoints, and a second take expose none. A queue ticket reserves no backend or view, but retains bounded backend/kind/authority metadata until the controller returns its exact ticket/lease promotion; that promotion is consumed once after scope and capacity revalidation. `inspect` snapshots report configured ceilings, queued views, reservations, spawnable, forwarder, and draining counts without claiming readiness or OS liveness. AdmissionLease and AdmissionPromotion are linear: neither implements Clone or Copy. A direct Git/job admission may enter raw spawn APIs; CommandKind::Provider is rejected there and must consume ProviderSpawnLease or ProviderForwarderSpawnLease. Forwarder admission errors return the untouched linear lease alongside the refusal. Issued provider capabilities share a registry launch state locked through OS spawn; logical release/revocation invalidates any still-pending listener/forwarder capability. Last-view release returns `BackendRelease::ReapOwned(capability)` and leaves its backend draining and physically reserved. Only `complete_reap(capability, DirectChildReap)` frees the reservation after checking controller/slot, backend and originating view, and the exact randomly generated direct-child identity recorded during typed spawn; forwarder completion applies the same checks. A reap from an arbitrary second child cannot settle it. A definite pre-child error carries non-cloneable `SpawnNeverStarted`; `settle_never_started` cancels only that reservation. An unissued capability may be cancelled explicitly. Timeout/drop never fabricates either settlement. Borrowed endpoints are never killed. Releasing or revoking one view preserves a compatible peer; the last owned view yields only a reap decision plus a separately reported uncertainty, never a claim that signal delivery or direct-child reaping completed.

Execution consumes Workspace's finite `AuthorityRevoked { worktree, old_epoch, reason }` value by matching worktree identity, incarnation, and old epoch. It returns a drain receipt containing logical views removed, release decisions, released admission leases, and an explicit reap-uncertainty bit. It neither broadens the event into a bus nor implements Intelligence's provider-compatibility semantics.

## Requests and responses

The current API validates `ValidatedHostInvocation`, `WorkspaceAuthority`, `ControlledCommand`, local policy, and an Execution-profile catalog before admission. A controlled command requires the declared executable to already be a stable regular file with readable bytes: construction opens it, records its filesystem object identity, and hashes its complete bytes, failing closed when the path is absent, unreadable, or not a regular executable. Immediately before OS spawn, Execution re-opens and re-measures the same path and refuses to launch if that later reading disagrees with the identity recorded at declaration. This detects a replacement that occurs between declaration and spawn preparation; it does not make the declare-then-spawn sequence atomic, and it does not close a same-user substitution raced into the narrow window between that pre-spawn re-check and the OS `exec` call itself, which remains open and is not eliminated by any verified mechanism in this codebase. Managed launch constructs an explicit search path from the Codex wrapper directory, provider directory, and profile-declared entries; it never uses ambient `PATH`. For v0.1, Workspace is the only producer of a Git command and receives its raw bounded stdout/stderr/exit evidence. Intelligence owns compatibility and logical leases; Execution never infers LSP compatibility or reads protocol stdout. `CommandKind::Job` is an internal controlled-child category, not a public arbitrary-command facility or a v0.1 check API.

Admission returns an admitted lease, bounded queue ticket, or typed refusal. Reservations are acquired before an owned process launch; queue tickets reserve nothing. Cancellation request, TERM/KILL delivery, direct-child reap, and descendant certainty are separate facts. Completed execution returns bounded stdout/stderr plus truncation, exit and timing evidence; it never declares Git-derived diff meaning, test coverage, or task completion.

Owned and borrowed handles have different capabilities. Borrowed endpoints may be observed/detached, never killed or reconfigured. A physical process is counted once where verified process identity permits dedup; marginal views and warmups reserve their own cost. Unknown borrowed process identity/resource usage is reported and conservatively reserved or refused under a required enforcement policy, never counted as zero.

## Bootstrap boundary

Current physical execution requires `WorkspaceAuthority`, but Workspace needs bounded Git discovery before it can issue final worktree authority. Discovery is a separate, Workspace-owned read-only effect and is not generic unauthorised execution.

Its required inputs are an active Assistance `BindingRef` correlated to the observed host state, that complete opaque state, the applicable Execution D03 gate, and local `git_discovery` policy. Missing/unsupported state or a closed D03 gate returns `unavailable`; lack of final Workspace authority never creates an unconfined child. Discovery needs no Intelligence LSP/provider compatibility permit and cannot mint Workspace authority, an Execution profile permit, or any other capability.

Execution preserves `state.sandboxCwd` exactly inside the sandbox-state JSON argument; for a supported local `file:` URI it derives only the local process cwd without rewriting that state value. It may invoke only a configured Git executable with one argv pattern: `git -C <exact raw candidate_cwd> <fixed query>`. `<candidate_cwd>` is the sole path operand and is carried without normalization, rewriting, or substitution; it must not replace `sandboxCwd`. The raw candidate is, however, the trusted directory a v2 profile permit binds the portable sandbox-cwd authority to: a managed state whose `sandboxCwd` is a different directory derives no v2 shape there and can only be admitted by a legacy v1 template's exact digest (T35B-r). The fixed queries are separate invocations of `rev-parse --show-toplevel` and `rev-parse --path-format=absolute --git-common-dir`, followed only by `worktree list --porcelain -z`. Each `rev-parse` result remains raw and separate for Workspace to parse as one terminal LF; path-valued results are never concatenated or newline-split. `worktree list` remains NUL-delimited. No caller-selected flags, environment, shell, additional path operands, provider/check/write class, or generic command is permitted.

`ValidatedGitDiscovery` is one non-cloneable validated spawn attempt; it consumes one linear admission lease, so cloning/replaying a failed attempt cannot repeat-mint settlement proofs. `DiscoverWorktreeRequest`, `DiscoveryOperationRef`, `GitDiscoveryQuery`, `GitDiscoveryPolicy`, `OwnedGitDiscovery`, and `GitDiscoveryEvidence` form the narrow discovery surface. `spawn` returns an owned handle whose borrowed wait may be cancelled without losing ownership. Reap/cancel returns `CompletedGitDiscovery { evidence, settlement }`; the adapter consumes settlement immediately, then passes only immutable evidence to Workspace. Operation references are bounded to 128 bytes and streams to 1 MiB; checked fixture constructors validate exit/drain metadata and mint no settlement rights. Each fixed query returns independent raw byte streams, exit status, truncation and elapsed time; Execution does not split terminal LF paths, parse NUL porcelain, concatenate results, mint WorktreeRef/authority/permit, or accept generic argv. Until a queued discovery receives another matching active use at owned spawn, it remains only a ticket.

## Admission and fairness

Use bounded queues with separate interactive/heavy classes, per-owner bounds, configurable burst and aging. Prevent starvation of eligible work; no preemption/latency guarantee is claimed inside an LSP implementation. Admission cost includes existing reservations and host headroom, not just frontend count. Cancellation/removal releases queued demand once. A lower config ceiling stops new excess admission and drains applicable work without killing unrelated peers.

Authority revocation cancels that actor's queued/owned jobs. A shared physical LSP remains while Intelligence presents surviving leases. Execution accepts a backend shutdown only from the backend owner after the relevant lease decision; revoking one view cannot kill a peer backend. Persistent quiescent retention has its own reservation and lease policy; inactive-workspace analysis is not allowed by retention.

`validate_workspace_read` rechecks current `ObservedSandboxState` and freshly consumed binding use against the durable-authorized root, current profile catalog, and local disabled-host policy. A managed state must independently prove read authority of the live state even when its `sandboxCwd` already is this worktree root, so admission through a narrower v2 shape never confers read authority; a disabled host keeps strict cwd equality. It fabricates no command or spawn and is required before native source reads or delivery of cached results when current MCP permissions may have changed.

### Per-path native-read proof (T36B)

The recheck takes an explicit scope. `ReadScope::WholeTree` keeps the restrictive T35B behavior — the recognized whole-root read grant AND no deny entries at all; every deny-bearing managed state refuses. `ReadScope::Path(&Path)` names one exact worktree-relative path: the deny-free fast path is tried first (it skips only policy matching, never path containment or no-follow enforcement), and otherwise the live cwd-bound shape v2 is derived and the pure `read_proof` decision decides. The shape is derived against the authoritative worktree root, so a state whose `sandboxCwd` is a different directory refuses derivation and the path is unproven; the cwd never enters shape serialization or digests.

`read_proof` returns `Proven` only when all four conditions hold: (1) **path and binding** — a nonempty relative path with normal components only (absolute paths, `.`, `..`, empty components, NUL, and backslashes refuse before normalization), joined component-wise beneath the trusted cwd; (2) **positive coverage** — a `Root` read/write rule, or a `WorkspaceRelative` read/write rule whose components prefix the target, with an absent `missing_path_behavior` (`MissingPath::Skip` grants do not establish authority, and temporary selectors or outside grants never cover a cwd path); (3) **path denies** — any ancestor-or-equal deny (ASCII case-folded) refuses, with no precedence solving; (4) **glob denies** — a glob whose folded literal base cannot reach the target is irrelevant, and otherwise the pattern must provably not match the target and every ancestor-or-equal prefix below the base (so matching an ancestor directory refuses its descendants), including base equality for wildcard-free stored remainders. A relevant glob whose depth below its base exceeds a present `glob_scan_max_depth` refuses; the limit is never used to declare a glob irrelevant.

The conservative matcher is anchored whole-path matching with an internal `Matches | DoesNotMatch | Unknown` result: literals (ASCII case-folded on both sides for deny matching only), `*` within one segment, `?` for exactly one character, and a complete `**` segment for zero or more segments, evaluated by bounded dynamic programming with no exponential backtracking. Brackets, braces, `!`, escapes, malformed separators, embedded `**`, and any non-ASCII produce `Unknown`, never literal fallback; only `DoesNotMatch` for every relevant comparison clears a glob. `Proven` means permission coverage under this model — never catalog admission, never a reusable filesystem capability.

Failure maps to the internal `RequestError::ReadPathUnproven`, which preserves the public `execution_profile` code and emits exactly `read_scope:path_unproven` (no paths); a real cwd mismatch stays `read_scope:sandbox_cwd_mismatch`. Consumers prove per path: `observe` its requested path; cached delivery every path the retained evidence represents (`Detail.source` plus the bounded diff provenance set covering rename sources and staged paths). An Activation status contains only the authority epoch and baseline/cache status, so delivery requires fresh durable authorization and binding liveness but no read-path proof. A completed Diff with recorded empty provenance also contains no worktree paths or bytes and needs no read-path proof; other path-less details keep the whole-tree gate. Cached disclosure adds a symlink `lstat` preflight over existing prefixes (missing targets allowed, other failures unproven) while the descriptor-relative `O_NOFOLLOW` reader remains the real guard at the actual read; diff authorizes the in-root index and applicable attribute-file metadata probes, every tracked metadata/byte read (staged included), every consistency reread, and untracked inspection through a required fallible `SnapshotRunner::authorize_read_path` with no permissive default. Batched `check-attr` receives NUL-delimited paths through an opened private 0600 stdin file under the same controlled Git admission; TypeScript resolution-input reads prove each auxiliary candidate.

Managed Codex semantic providers run through `codex sandbox --sandbox-state-json` with the observed host state, so the OS enforces its read denies on provider reads. The requested source and every returned definition/reference path still require current per-path proof. Project checks run under their own Seatbelt policy. A Codex profile with a root read grant may run checks when its path denies and credential globs (`**/*.key`, `**/*.pem`, `**/.env`, `**/.env.*`) translate to Seatbelt denies and fixed daemon-side project probes are path-proven. The check policy intersects those denies with every checker grant; Python checks use no-follow config reads and prove every interpreter symlink hop. Glob-base deny matching folds ASCII case before a diagnostic path is probed. Deny-bearing checks never run the Git worktree fingerprint. Persistent check caches and sibling Rust cache clones are partitioned by the effective deny set; an older policy generation cannot publish a completion after the policy narrows. Denied diagnostic paths are dropped before caching and cannot contribute to displayed counts. Unsupported deny syntax or an unproven check input remains `read_restricted`: no check or project fingerprint is scheduled and status and Problems return content-free `unavailable: read_restricted` language states. A later changed or unknown Codex observation cancels pending or running checks, suppresses this binding's cached diagnostics and native-hook triggers, and keeps it unavailable until a new binding. A restriction observed while Start is pending wins over Start's older profile at activation. Native hooks have no current sandbox metadata and use this latest managed restriction state. Claude still requires whole-tree read authority with no read exclusions because it supplies no host sandbox metadata. A current `ide.edit` call separately proves its exact path before Workspace prepares and reads the target. Unsupported check read scope uses `read_scope:whole_tree_unproven`; `read_scope:sandbox_cwd_mismatch` identifies a disabled-host cwd mismatch.

### Known limits

If a profile narrows while a fingerprint is already running, that one in-flight `git ls-files --exclude-standard` listing may finish: the blocking fingerprint task is not cancelled. A later check run for the restricted binding is refused.

## Process and platform boundary

Execution owns Unix process/resource adapters, strong process identity, pipe draining, signal escalation and cleanup. Retained bytes are bounded while pipes continue draining. A Child handle drop/timeout is not cleanup proof. Wait/reap direct children and legally adopted children; other descendants are tracked and their observed exit/remaining uncertainty is reported. Do not promise waitpid rights over arbitrary grandchildren. Numeric PID alone never authorizes a signal after restart.

TERM/grace/KILL and recovery have configurable budgets. Release physical reservation only after exit evidence or an explicitly conservative recovery handoff. Identity/cleanup uncertainty is quarantined and exposed, not converted into success. Process groups do not contain intentionally escaped processes; unmanaged native shell remains outside this guarantee.

Owned captured/protocol child handles now retain a private drop guard through consuming
reap futures. If a handle or pending reap is dropped, the guard requests immediate KILL
for its still-unreaped owned process group and direct child, aborts its owned output drain
tasks, and leaves best-effort direct-child reaping to Tokio. Spawn setup also enables
Tokio's direct-child `kill_on_drop` fallback. A successfully reaped child has no retained
signal target, and borrowed endpoints never acquire this guard. Signal delivery failure,
runtime shutdown, and escaped descendants remain uncertain; drop is not reap evidence.

Admission leases are separate controller reservations, so abnormal drop cannot return a
successful reap receipt or free capacity. `running_count` counts reservations, including
these uncertain slots, rather than observed live OS processes. The current bounded recovery
path is to stop further use of the affected owner/controller, obtain independently verified
cleanup evidence, and recreate that controller with the owning daemon lifecycle. Automatic
persistent reconciliation after daemon restart is not implemented. A restart or missing PID
alone does not prove cleanup, authorize signalling an old numeric PID, or prove that a
retained backend is live; unresolved cleanup must remain quarantined. Normal explicit reap
returns one non-cloneable settlement proof; protocol results expose no second raw lease.

Linux hard_required uses available delegated cgroups/controllers or returns unavailable. macOS resource sampling is monitoring, not a hard RSS guarantee. Soft-budget overage stops further admission and applies configured owned-process policy; OS-enforced memory behavior cannot be invented by Tokio.

Captured children return `CompletedProcess { evidence: CapturedProcessEvidence, settlement: DirectChildReap }`. Evidence is immutable, capped at 8 MiB per retained stream, and contains no admission capability; `ReapedProtocolProcess` retains exclusive protocol ownership and reports stderr plus direct-child settlement. Workspace/Changes never receive settlement tokens. Controller-scoped reservation identities prevent equal local numeric IDs from crossing controllers. Shared forwarder slots settle independently through `complete_forwarder_reap`; logical detach never frees them.

Owned process `cancel_bounded(&mut self, grace, deadline)` retains the handle on timeout for a supervised reaper handoff. Consuming reap has separate finite exit/drain bounds; protocol reap applies its deadline to exit and stderr. TERM grace and wait deadlines cannot exceed 60 seconds; expiry returns no proof. Direct-child exit never establishes descendant termination. Protocol stdout stays open until the child exits, and graceful Session shutdown drains provider EOF, avoiding client-induced SIGPIPE.

The TypeScript normal-success path is narrower: after successful LSP shutdown it sends `exit`, observes protocol EOF, waits for a successful bridge exit within the deadline, and reaps that direct child without sending `TERM` or `KILL`. Any failure, timeout, cancellation, forced signal, or lost owning helper is unsuccessful and quarantines the exact profile for the owner lifetime. Abnormal cleanup may use one crate-private TypeScript path that retains the direct child unreaped, sends process-group `TERM`, waits the fixed grace without reaping, sends process-group `KILL` plus direct-child kill, and only then reaps the direct child. It never signals after direct reap. This path does not add a generic supervisor, subreaper, grandchild `waitpid` claim, verified-descendants result, or process-group containment claim.

`take_process_identity` transfers one opaque non-cloneable launch correlation containing private randomness and direct PID. Only actual wait mints the cloneable, non-authorizing `ReapedChildIdentity` on captured evidence. A scratch guard may match that identity to its armed child; fixture evidence cannot mint it. Uncertain cleanup retains or quarantines the resource guard, or transfers it with the still-owned child to a supervisor.

## Evidence and acceptance boundary

The current contract harness, `tests/execution_contract.rs`, proves profile rejection, bounded admission, captured output drain, cancellation versus direct-child reap, protocol-stdout exclusivity, and borrowed-endpoint refusal. It does not prove host binding, sandbox replay, durable process identity, or provider isolation.

The D03 acceptance experiment must use an Assistance-captured state from a real D01-bound invocation, invoke the managed child through the exact Codex sandbox argv, and report allowed/denied operations that match the host contract. It must additionally observe bounded output, direct-child reap, and uncertainty about descendants. Until that experiment is recorded for the Execution template/version, managed provider effects remain unavailable. No v0.1 evidence grants a public check or write surface.

One macOS managed-state fixture has completed this subprocess evidence step. Its shape used `permissionProfile.type=managed`, restricted filesystem entries, restricted network, and a `file:` `sandboxCwd` URI retained unchanged for the Codex argument. When that inherited cwd differed from the authoritative worktree, an operator-pinned `/usr/bin/env -C` trampoline changed directory inside the unchanged sandbox. An owned child could write an allowed fixture file; writes to a read-only `.git` path and an approved disposable path outside the profile failed; a loopback connection to a controlled listener failed; bounded stdout/stderr drain and direct-child reap completed. Codex also accepted the complete captured JSON after semantic `serde_json::Value` reserialization, so the transport boundary requires field/value preservation rather than wire whitespace or key-order preservation. Assistance-consumed parent and native-child bindings then completed fixed Git discovery and real shared-gopls Context in distinct worktrees under that state. This is evidence for that observed class/shape only; it does not claim every managed profile, arbitrary roots, or generic network behavior.

## Retention and failure isolation

Intelligence may request a budgeted quiescent retained-backend lease for warm handoff; the lease is tied to the compatible backend/resource identity, not an old actor's active authority. Retention never exempts physical memory/process accounting or permits inactive-workspace analysis. Eviction/drain honors surviving active views and borrowed ownership; it never kills a peer or clears borrowed caches.

Admission/process/provider failure completes affected tickets within their declared control deadline or reports effect/cleanup uncertainty. It does not hold unrelated queues, native tools or host turn completion. Provider restart has one bounded owner and consumes the shared call/retry budget; nested layers cannot multiply retries. A breaker-open backend yields fast unavailable/queued-under-policy rather than repeated spawn storms. Execution returns evidence; it does not install an agent-wide completion gate.
