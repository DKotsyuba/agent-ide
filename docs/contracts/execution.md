# Governed execution and process evidence

Revision: r9 (Workspace v0.1-r4 direct boundary accepted). Provider: Execution. Direct providers: Assistance supplies consumed active binding use and the admitted worktree; Workspace supplies controlled Git intent and worktree authority; Application supplies config/store mechanics only. Direct consumers: Workspace consumes raw Git execution results; Intelligence consumes owned protocol/process leases; Application persists Execution-owned records. Changes composes Workspace raw Git results and does not directly spawn. Vocabulary: [common](common.md).

## Path policy and spawn gate

Owned children run as ordinary processes of the daemon's user. Execution replays no host sandbox, admits no host permission profile, and holds no catalog of accepted sandbox states: the product's only path policy is the launcher `allowed_roots` list, which Assistance enforces before a request reaches Execution — the activation root, the discovered Git worktree root and the Git common directory must all lie below a configured root (`outside_allowed_roots` otherwise), and every absolute path a provider resolves outside the worktree is admitted by the same predicate (`admit_path`). Execution therefore accepts a physical-effect request only with a consumed peer-validated active binding use, full Workspace worktree ID/incarnation/root/epoch after authority exists, a controlled command, and immutable local policy. Assistance creates the binding generation only after its real D01 proof; an absent, bare, stale, or heuristic binding is `unavailable`, never a candidate for admission. Workspace constructs and validates raw Git argv. Intelligence chooses provider topology and a declared profile, then consumes an owned protocol child.

An active use is consumed once to admit/validate a request and must be freshly consumed again immediately before an owned child starts. A queued request retains only its immutable binding generation; a stop between queue and dequeue makes its later spawn refuse (`MissingActiveBindingUse`). A locally admitted child may finish after stop, but a stopped binding never by itself authorizes backend termination. Workspace sends the scoped `AuthorityRevoked { worktree_ref, old_epoch, reason }` path to Intelligence, which fences/releases its logical view and asks Execution to reap only an owned unshared process; shared peer cleanup follows lease policy.

**Git metadata revalidation.** Workspace carries its native-validated canonical common Git directory into Execution's worktree authority; for a linked checkout this covers the separate per-worktree administrative directory beneath `common/worktrees`. For a `CommandKind::Git` command, Execution revalidates the live `.git` → admin → common backpointer cycle at validation and again immediately before spawn, so a queued Git operation never silently reads a different repository after `.git` changed (`GitMetadataInvalid`). Provider and job commands run no Git and skip this check. This is a correctness check, not a write guard: nothing in Execution prevents a child from writing where the daemon's user may write; that is the owner's explicit decision (an agent with its own shell needs no second sandbox).

For TypeScript support, Execution accepts only the exclusive per-worktree lease chosen by [TYPESCRIPT-r3](intelligence-v0.2.md). Its controlled command is the accepted Node executable followed by the immutable bridge invocation `typescript-language-server --stdio`; the accepted `tsserver.path` and every closure member are re-measured immediately before spawn. No ambient `PATH`, npm, plugin, network, syntax-server, or automatic-typing-acquisition input is admitted. Runtime descendant evidence remains `Unverified`; support instead depends on separate release-pinned normal-shutdown records.

## Provider leases

Execution's `ProviderLeaseRegistry` has finite total and per-backend view ceilings and uses the central `AdmissionController` only for a new owned physical backend. Pending requests count against both view ceilings before promotion. Compatible shared views retain one heavy-process reservation and count separately as forwarders. An exclusive backend accepts one view. A new owned backend exposes its reservation only as a one-time view-bound spawn capability consumed by Execution's protocol-child setup; shared reuse, borrowed endpoints, and a second take expose none. A queue ticket reserves no backend.

Execution consumes Workspace's finite `AuthorityRevoked { worktree, old_epoch, reason }` value by matching worktree identity, incarnation, and old epoch. It returns a drain receipt containing logical views removed, release decisions, released admission leases, and an explicit reap-uncertainty bit. It neither broadens the event into a bus nor implements Intelligence's provider-compatibility semantics.

## Requests and responses

The current API validates `ValidatedHostInvocation`, `WorkspaceAuthority`, `ControlledCommand`, and `LocalExecutionPolicy` (program allowlist, argv byte ceiling, environment entry ceiling) before admission. A controlled command requires the declared executable to already be a stable regular file with readable bytes: construction opens it, records its filesystem object identity, and hashes its complete bytes, failing closed when the path is absent, unreadable, or not a regular executable. Immediately before OS spawn, Execution re-opens and re-measures the same path and refuses to launch if that later reading disagrees with the identity recorded at construction. The command always runs in the authoritative worktree with a cleared environment plus exactly the entries the peer supplied.

Admission returns an admitted lease, bounded queue ticket, or typed refusal. Reservations are acquired before an owned process launch; queue tickets reserve nothing. Cancellation request, TERM/KILL delivery, direct-child reap, and descendant certainty are separate facts. Completed execution returns bounded stdout/stderr plus truncation, exit and timing evidence; it never declares Git-derived diff meaning, test coverage, or task completion.

Owned and borrowed handles have different capabilities. Borrowed endpoints may be observed/detached, never killed or reconfigured. A physical process is counted once where verified process identity permits dedup; marginal views and warmups reserve their own cost. Unknown borrowed process identity/resource usage is reported and conservatively reserved or refused under a required enforcement policy, never counted as zero.

## Bootstrap boundary

Current physical execution requires `WorkspaceAuthority`, but Workspace needs bounded Git discovery before it can issue final worktree authority. Discovery is a separate, Workspace-owned read-only effect and is not generic unauthorised execution.

Its required inputs are an active Assistance `BindingRef`, the admitted (canonical) activation root as the raw candidate, and local `git_discovery` policy. Lack of final Workspace authority never creates an unconfined child; discovery cannot mint Workspace authority or any other capability. Execution may invoke only a configured Git executable with one argv pattern: `git -C <candidate> <fixed query>`, run in the candidate directory. `<candidate>` is the sole path operand and is carried without rewriting.

`ValidatedGitDiscovery` is one non-cloneable validated spawn attempt; it consumes one linear admission lease, so cloning/replaying a failed attempt cannot repeat-mint settlement proofs. `DiscoverWorktreeRequest`, `DiscoveryOperationRef`, `GitDiscoveryQuery`, `GitDiscoveryPolicy`, `OwnedGitDiscovery`, and `GitDiscoveryEvidence` form the narrow discovery surface. `spawn` returns an owned handle whose borrowed wait may be cancelled without losing ownership. Reap/cancel returns `CompletedGitDiscovery { evidence, settlement }`; the adapter consumes settlement immediately, then passes only immutable evidence to Workspace's pure parser.

## Admission and fairness

Use bounded queues with separate interactive/heavy classes, per-owner bounds, configurable burst and aging. Prevent starvation of eligible work; no preemption/latency guarantee is claimed inside an LSP implementation. Admission cost includes existing reservations and host headroom, not just frontend count. Cancellation/removal releases queued demand once. A lower config ceiling stops new excess admission and drains applicable work without killing unrelated peers.

Authority revocation cancels that actor's queued/owned jobs. A shared physical LSP remains while Intelligence presents surviving leases. Execution accepts a backend shutdown only from the backend owner after the relevant lease decision; revoking one view cannot kill a peer backend. Persistent quiescent retention has its own reservation and lease policy; inactive-workspace analysis is not allowed by retention.

Project checks run under their own Seatbelt policy (see [assistance-launcher](../assistance-launcher.md)); that confinement is cache hygiene for background builds, not a permission model, and it derives nothing from a host sandbox.

## Process and platform boundary

Execution owns Unix process/resource adapters, strong process identity, pipe draining, signal escalation and cleanup. Retained bytes are bounded while pipes continue draining. A Child handle drop/timeout is not cleanup proof. Wait/reap direct children and legally adopted children; other descendants are tracked and their observed exit/remaining uncertainty is reported. Do not promise waitpid rights over arbitrary grandchildren. Numeric PID alone never authorizes a signal after restart.

TERM/grace/KILL and recovery have configurable budgets. Release physical reservation only after exit evidence or an explicitly conservative recovery handoff. Identity/cleanup uncertainty is quarantined and exposed, not converted into success. Process groups do not contain intentionally escaped processes; unmanaged native shell remains outside this guarantee.

Owned captured/protocol child handles retain a private drop guard through consuming reap futures. If a handle or pending reap is dropped, the guard requests immediate KILL for its still-unreaped owned process group and direct child, aborts its owned output drain tasks, and leaves best-effort direct-child reaping to Tokio. Spawn setup also enables Tokio's direct-child `kill_on_drop` fallback. A successfully reaped child has no retained signal target, and borrowed endpoints never acquire this guard. Signal delivery failure, runtime shutdown, and escaped descendants remain uncertain; drop is not reap evidence.

Admission leases are separate controller reservations, so abnormal drop cannot return a successful reap receipt or free capacity. `running_count` counts reservations, including these uncertain slots, rather than observed live OS processes. The current bounded recovery path is to stop further use of the affected owner/controller, obtain independently verified cleanup evidence, and recreate that controller with the owning daemon lifecycle. Automatic persistent reconciliation after daemon restart is not implemented. A restart or missing PID alone does not prove cleanup, authorize signalling an old numeric PID, or prove that a retained backend is live; unresolved cleanup must remain quarantined. Normal explicit reap returns one non-cloneable settlement proof; protocol results expose no second raw lease.

Linux hard_required uses available delegated cgroups/controllers or returns unavailable. macOS resource sampling is monitoring, not a hard RSS guarantee. Soft-budget overage stops further admission and applies configured owned-process policy; OS-enforced memory behavior cannot be invented by Tokio.

Captured children return `CompletedProcess { evidence: CapturedProcessEvidence, settlement: DirectChildReap }`. Evidence is immutable, capped at 8 MiB per retained stream, and contains no admission capability; `ReapedProtocolProcess` retains exclusive protocol ownership and reports stderr plus direct-child settlement. Workspace/Changes never receive settlement tokens. Controller-scoped reservation identities prevent equal local numeric IDs from crossing controllers. Shared forwarder slots settle independently through `complete_forwarder_reap`; logical detach never frees them.

Owned process `cancel_bounded(&mut self, grace, deadline)` retains the handle on timeout for a supervised reaper handoff. Consuming reap has separate finite exit/drain bounds; protocol reap applies its deadline to exit and stderr. TERM grace and wait deadlines cannot exceed 60 seconds; expiry returns no proof. Direct-child exit never establishes descendant termination. Protocol stdout stays open until the child exits, and graceful Session shutdown drains provider EOF, avoiding client-induced SIGPIPE.

The TypeScript normal-success path is narrower: after successful LSP shutdown it sends `exit`, observes protocol EOF, waits for a successful bridge exit within the deadline, and reaps that direct child without sending `TERM` or `KILL`. Any failure, timeout, cancellation, forced signal, or lost owning helper is unsuccessful and quarantines the exact profile for the owner lifetime. Abnormal cleanup may use one crate-private TypeScript path that retains the direct child unreaped, sends process-group `TERM`, waits the fixed grace without reaping, sends process-group `KILL` plus direct-child kill, and only then reaps.

`take_process_identity` transfers one opaque non-cloneable launch correlation containing private randomness and direct PID. Only actual wait mints the cloneable, non-authorizing `ReapedChildIdentity` on captured evidence. A scratch guard may match that identity to its armed child; fixture evidence cannot mint it. Uncertain cleanup retains or quarantines the resource guard, or transfers it with the still-owned child to a supervisor.

## Evidence and acceptance boundary

The contract harness, `tests/execution_contract.rs`, proves bounded admission, captured output drain, cancellation versus direct-child reap, protocol-stdout exclusivity, borrowed-endpoint refusal, and the local request ceilings. Live host acceptance ([macos-acceptance](../macos-acceptance.md)) proves that activation, context, diff and edit work through each host route inside an allowed root and refuse outside one; no per-host sandbox evidence is required or recorded.

## Retention and failure isolation

Intelligence may request a budgeted quiescent retained-backend lease for warm handoff; the lease is tied to the compatible backend/resource identity, not an old actor's active authority. Retention never exempts physical memory/process accounting or permits inactive-workspace analysis. Eviction/drain honors surviving active views and borrowed ownership; it never kills a peer or clears borrowed caches.

Admission/process/provider failure completes affected tickets within their declared control deadline or reports effect/cleanup uncertainty. It does not hold unrelated queues, native tools or host turn completion. Provider restart has one bounded owner and consumes the shared call/retry budget; nested layers cannot multiply retries. A breaker-open backend yields fast unavailable/queued-under-policy rather than repeated spawn storms. Execution returns evidence; it does not install an agent-wide completion gate.
