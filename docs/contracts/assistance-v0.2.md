# Assistance v0.2 contract

Revision: EDIT-r1 (proposed). Provider: Assistance. Direct consumers: Application, Changes, and host adapters. Vocabulary: [common](common.md).

Agent-facing rendering follows [AGENT-CONTENT-r2](agent-content-v0.2.md) and [harness-reply-v1](harness-reply-v1.md): every validated PeerReply becomes exactly one deterministic compact model text block and no `structuredContent` in production (a `test-seams` build may keep the typed copy as a test oracle). The public catalog is ten tools on both hosts and public `ide.context` is removed. Only typed `Error` sets `isError`. The facade and retained Diff pagination use the same final serialized CallToolResult measurement; only owner Complete text may shrink, at UTF-8 boundaries, and Diff fitting removes whole hunks instead of cutting text. Rendering is host-independent and neither adds a second response schema nor infers diagnostics absent from the typed PeerReply.

## Sixth closed MCP method

Assistance owns the sixth and only added MCP method of this EDIT-r1 boundary, `ide.edit`, alongside `ide.start`, `ide.diff`, `ide.inspect`, and `ide.stop` (historically also the since-removed `ide.context`; the surface is now ten tools, see [tools v0.4](tools-v0.4.md)). Its parameters and results are exactly the canonical request/outcomes in [Changes v0.2](changes-v0.2.md); Assistance validates the closed schema, current host binding, active authority, and bounded rendering, then delegates. It neither resolves paths, writes files, settles receipts, nor interprets Application storage rows.

The only success rendering is a bounded `created`, `replaced`, or `unchanged` result with operation/path references and an Assistance-owned closed diagnostic projection. The retained post-edit observation (the deprecated, unadvertised `source_ref`) is kept only when the refreshed observation exactly matches the Workspace post-read bytes and no native-write epoch intervened; otherwise the successful effect is settled as `outcome_unknown` and cannot chain unseen bytes. Edits are symbol-first and need no file-version reference. Changes persists only the filesystem receipt; it never persists diagnostic text or readiness. The projection is `current_clean`, `current_reported` (bounded messages/delta), `not_analysed` (bounded reason: the completed check never analysed the file; never clean), `unknown`, or `pending` only when a real same-binding inspectable detail reference exists. Current states require a matching provider generation and explicit versioned diagnostic result; silence, timeout, unavailable providers, stale generations, and incomplete correlation are `unknown`, never clean. Diagnostics reserve time for known receipt settlement, so an incomplete refresh returns the known edit outcome with `unknown` diagnostics rather than degrading it. `current_reported` lists the problems for another symbol edit, `current_clean` needs no follow-up, and inspectable `pending` or `unknown` diagnostics are read with `ide.inspect` only when a real detail reference exists; the check result is retained and, when Bridge is configured, delivered automatically (carrier and timing owned by Bridge), with no polling. `stale_source`, `unsafe_target`, conflicts, no-effect results, unavailable, and unknown are rendered as compact typed outcomes. `outcome_unknown` instructs inspection of the named target before another mutation; it never recommends replay. Tool failure remains fail-open for native work.

Claude and Codex route `ide.edit` through the daemon after the same binding checks. Codex rechecks the current host profile's read proof for the exact target before Workspace's edit preparation opens it; a source retained under an earlier, broader profile cannot authorize a read after narrowing. A refused proof settles as `unavailable_before_dispatch` with no target effect. These host routes remain adapters, not alternate edit contracts.

Success: a bound active call delegates a complete request and returns `replaced` with a current clean/report projection when its provider establishes it before the bounded deadline; otherwise diagnostics are `unknown`. Error: an unbound Claude call returns `unavailable_before_dispatch` and does not mint a receipt or write.

## Gates

A substitute gate proves only schema closure, rendering, host-binding rejection, and native-fallback presentation. A real integration gate proves the sixth method through the actual closed IPC route and each supported host adapter; it consumes the Workspace/Changes effect gates and does not substitute host fixtures for them.
