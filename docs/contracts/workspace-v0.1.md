# Workspace v0.1 contract

Revision: v0.1-r9 (proposed; direct consumer acceptance pending). Provider: Workspace. Direct consumers: Assistance, Execution, Application, and Changes; Intelligence consumes only the stated observations when its v0.1 slice arrives. Shared vocabulary: [common](common.md).

## Ownership and boundary

Workspace owns Git/worktree identity and incarnation, authority grants and revocation after host verification, source observations and session baselines, worktree ownership/lifecycle, and raw Git intent/parsing. Its Git adapter belongs under `workspace/git`.

Workspace does not prove host identity, spawn a process, own SQLite mechanics or migrations, provide LSP semantics, semantically enrich a diff, run checks, write source, keep an edit journal, interpret a WorkBundle, or compile task context. Assistance owns host proof and the five MCP schemas; Execution owns physical Git execution; Application owns transaction and migration mechanics; Intelligence owns semantic lookup; Changes owns v0.1 bounded diff composition, with ChangeSet persistence and semantic enrichment beginning in v0.2.

The only v0.1 logical tools are `start`, `context`, `diff`, `inspect`, and `stop`. No future tool is registered as a placeholder.

## Inputs and activation

Assistance supplies a fresh opaque `ActiveBindingUse` for a `BindingRef`, plus the separately correlated `ObservedSandboxState`. A bare actor ID, call ID, cwd, HEAD, model argument, PID, or time correlation is not authority. Workspace consumes/rechecks binding liveness before every authority-scoped use; a revoked binding yields no data or new authority.

Before authority exists, Workspace may ask Execution for the accepted read-only discovery edge. The request carries the active binding use, observed sandbox state, raw candidate Unix path, and a stable operation ID. Execution applies its D03/local `git_discovery` gate, preserves `sandboxCwd`, and runs only the fixed `git -C <candidate>` discovery queries. Discovery returns raw bounded evidence or `unavailable`; it cannot create an authority or profile permit.

Workspace parses discovery as raw bytes. `DurableWorkspace::resolve_worktree` opens real root, repository, and common directories without symlink components, fingerprints device/inode plus creation time for all three, and retains their descriptors for the owner lifetime. SQLite mints an incarnation and OS-random nonce; callers cannot select them, and the nonce separates otherwise identical paths/integers from independent databases. Randomness is a lifecycle discriminator, not evidence of recreation. A changed creation-aware identity at the same path gets a new incarnation only after the old record has no active grant. A missing path mints nothing. Moves remain unavailable until explicit reconciliation. The durable claim uses an Application stable activation operation ID; an exact retry resolves the same immutable start receipt. `OutcomeUnknown` is reconciled by lookup and never blindly replayed.

## Offered values and behavior

`WorktreeRef` contains an opaque worktree ID and incarnation plus the raw Unix worktree path, repository root, Git common directory, and private native identity evidence. `from_discovery` remains an unverified reference/fixture constructor: its caller-chosen incarnation cannot pass durable activation. A changed path, common directory, or identity evidence creates/requires reconciliation; HEAD alone never identifies a worktree.

`WorkspaceAuthority` is opaque and bound to one canonical `WorktreeRef`, active `BindingRef`, durable owner boot, and authority epoch. It is granted only after the preceding sequence succeeds. Concurrent claims for one worktree admit one actor; an actor with another active worktree is refused. A retried `stop` carries its expected authority: an old stop never revokes a newly activated generation.

`close_worktree(operation, worktree)` is an explicit durable lifecycle transition. It requires the exact currently verified native object and no active grant, and returns a non-Clone `VerifiedWorktreeClosure`. Exact stable-operation retries recover its historical receipt; changed arguments conflict. A later resolution, even of the same native directory, mints a new incarnation/nonce. Actor stop and Assistance handoff do not imply worktree closure; v0.1 has no external close ingress wired to this API.

Creation-time evidence uses Rust's native `Metadata::created` (birthtime on macOS and filesystem/kernel-supported creation time on Linux). Unsupported, pre-epoch, or zero timestamps fail closed. This does not claim portability to filesystems without creation identity or identity continuity across filesystem restore/metadata forgery. Held descriptors prevent live inode reuse, while creation-aware comparisons protect ordinary reuse across process restarts. The additive v2 migration retires legacy rows without creation evidence/nonces; it does not reinterpret their old device/inode keys as verified current identity.

`DurableWorkspace::open` admits the identity/authority/baseline schema through Application, advances the persistent boot and epoch clocks, and fences prior active grants. The product holds one owner per boot; another open is an explicit new boot. `activate` returns an immutable `StartReceipt`; `authority` and `authorize` additionally require a fresh matching Assistance binding, unchanged native identity, an active durable claim, and the current boot. Old receipts remain inspectable after restart but cannot revive authority. Binding fingerprints used by a prior boot or stopped grant cannot authorize a new start ID. Fingerprints are domain-separated and length-framed; raw channel binding data is not persisted.

Start outcomes, actor/worktree exclusivity, epochs, and exact stop outcomes live in Workspace tables within Application transactions. Durable revoke accepts the immutable start receipt, so a stop outcome can be recovered after process restart without reconstructing live authority. SQL uniqueness constraints enforce one active actor per worktree and one active worktree per actor. Exact retries return committed outcomes; a fresh validated MCP call may retry the same activation ID because per-call IDs are not durable operation identity. Changed actor, channel/binding generation, or worktree intent under that ID conflicts. `AuthorityRegistry` remains a non-authoritative in-process fixture/cache utility. Its stamps cannot satisfy durable product admission, and the remaining product wiring must use the durable owner at every consumption boundary.

After Assistance validates `stop` while the binding is live, it calls `stop_binding(authority.binding_ref)` before or atomically with Workspace final revocation. Workspace finalization does not consume or reactivate that now-revoked binding. If the host-binding stop handoff is absent, Workspace records `revocation-incomplete` and refuses all later authority use. A later explicit `start` creates a fresh binding generation.

Workspace sends one finite typed `AuthorityRevoked { worktree_ref, old_epoch, reason }` directly to Intelligence. `worktree_ref` includes its incarnation. Intelligence fences new view/query/diagnostic work, releases only that logical view, and returns a drain receipt; it asks Execution to reap only an owned unshared backend, never a surviving shared peer. This is a direct call/result, not an event bus. `stop` never rolls back files, closes a worktree, or stops peers.

`SourceObservation` contains an opaque reference, `WorktreeRef`, monotonic source sequence, raw path, byte digest and length, source revision, and explicit coverage. Currentness requires exact equality with the latest complete persisted row for that raw path; matching only its sequence is insufficient. A newer or same-sequence but differently identified observation is stale. A source revision is distinct from HEAD, index, session baseline, task BASE, and submitted COMMIT. Unknown or partial coverage is never reported as clean. Currentness and reload queries allocate no Application receipt, so receipt retention cannot affect exact read-only recovery. Recording an observation allocates none either: it is local append-only bookkeeping whose operation id is unique per daemon and source sequence, and the row itself carries that id, so a repeated or ambiguous record is classified from the row (`AlreadyRecorded`, `Conflict`, or unknown while the row is absent). One receipt per observed file version would only grow the receipt ledger (settled receipts are retired behind the replay horizon, `application.md`) without any replay it could prevent.

For a `head`, `staged`, or `unstaged` request, Workspace validates authority, worktree incarnation and epoch, and supplies Changes exact left/right Git identities, bounded patch comparison evidence, NUL-safe paths/status/conflicts, separately listed untracked files, and baseline completeness/provenance only as context. A baseline never substitutes for any of those three comparison modes. Workspace derives identities only from complete fixed read-only HEAD, index, and working-state evidence; an unborn HEAD or truncated/failed input is explicit rather than an identity. Workspace parses NUL-delimited Git data and terminal-LF discovery paths without UTF-8 assumptions and keeps Git HEAD/index/baseline facts separate from source bytes. Changes composes the bounded logical diff result; Assistance renders it.

`GitSnapshot` is minted only by the bounded Workspace collector. It contains one exact `GitScope`, nonzero operation capture generation, operation reference, comparison identities, raw status categories, and one `PathSnapshot` for each selected supported tracked path. A path record retains its exact raw path, XY state, HEAD/index/worktree modes, full object IDs, bounded patch, and (for head/unstaged) exact source digest/length plus an optional matching persisted source revision/sequence. Byte identity remains separate from executable mode. Both status scope and tracked status entries match the selected mode; counts never include an unstaged-only path in staged output. Unmerged paths retain their actual stage 1/2/3 modes and full OIDs; a record without any actual stage is rejected, and derived conflict XY is explicitly unknown rather than fabricated as UU. Because v0.1 does not capture an exact working-content identity for conflicted paths, a result containing them reports unknown rather than current freshness. Changes consumes this typed collection; raw Git output alone cannot authorize a composed diff.

The collector runs only fixed `rev-parse --verify --quiet HEAD`, `ls-tree -r -z --full-tree HEAD`, `ls-files --stage -z`, `ls-files --debug -z`, `rev-parse --path-format=absolute --git-path index`, fixed `config --get` queries for `core.autocrlf`, `core.attributesFile`, and `core.eol`, and `ls-files --others --exclude-standard -z` metadata queries, plus bounded NUL-stdin `check-attr -z` batches for prospective stat skips. Porcelain parsing remains available for standalone inspection, with strict full 40/64 hexadecimal object IDs and all-zero names representing absent sides. **Neither repository `status` nor repository `diff` is executable through `GitReadIntent`: even status can invoke clean/process filters while checking working content.** Raw X status comes from HEAD/index object and mode equality; Y comes from exact Workspace source bytes and descriptor-derived regular-file mode on candidate paths. HEAD/index inequality selects staged candidates. The active index path receives the same worktree-relative read proof and no-follow, root-checked metadata probe; a missing index is empty, while a linked index outside the proven root makes every tracked path a byte-capture candidate. For remaining paths, a live per-path read proof precedes a no-follow, root-checked native metadata probe. A stat mismatch, an entry mtime at or after the index file mtime, or nonzero index flags selects that path for source-byte capture. For other paths, per-path proofs cover applicable `.gitattributes` and Git-info attributes files before Git evaluates only `text`, `crlf`, `eol`, `ident`, `filter`, and `working-tree-encoding`; only paths whose queried conversion attributes are all exactly `unspecified` and whose `core.autocrlf` is off may skip byte capture. Every other value, including `set` and literal `unset`, forces capture. `core.eol` affects only text-marked paths, already selected by those attributes. A nonexistent `core.attributesFile` yields unspecified attributes and does not force capture. A nonempty `check-attr` stderr, truncated or malformed output, or an unproven attribute source makes the whole query untrusted and forces byte capture of all prospective skips under the separate transient hash ceiling. Attribute results and source-file presence are rechecked before completion; tracked attribute files count even when missing locally because Git may use their index copy. Assume-unchanged and skip-worktree flags therefore do not suppress worktree changes. Intent-to-add's empty-blob entry is absent from the staged side and appears as an unstaged addition even when the source is empty; if its worktree file disappears, the placeholder retains an unstaged deletion. The path proof and metadata comparison repeat before completion, and the index timestamp is bracketed, so a skipped path changing during the attempt fails closed. This is a stat-and-racy-timestamp proof of unchanged paths, with the same undetectable-ABA limit as the capture window; it does not claim to detect a file mutation that preserves every compared native stat field. Like Git status, changing `core.autocrlf` after checkout does not revisit an otherwise clean non-racy file until it is touched or renormalized. Index stages 1–3 remain conflicts and never produce guessed hunks. Rename inference is unsupported: a rename is represented as separate raw delete/add paths. Ignored files are excluded by the untracked query and are not scanned separately.

Blob reads use `cat-file blob <full-oid>`, deduplicated by strict object ID. Cat-file does not prove the returned bytes match that object name: every newly read blob is copied to a private 0600 file and checked by fixed `git --no-lazy-fetch hash-object --no-filters -- <private-blob>`. Git uses the selected repository object format (SHA-1 or SHA-256); the full returned OID must equal the requested OID before bytes enter the cache. Hashing never writes an object. `GIT_NO_LAZY_FETCH=1`, the mandatory global `--no-lazy-fetch` option, and `GIT_NO_REPLACE_OBJECTS=1` disable promisor fetching and replacements. Unsupported raw-collection Git binaries return `UnsupportedSnapshotGit` before object access; there is no weaker fallback. The cleared Execution environment disables system/global Git configuration and system attributes; metadata commands disable fsmonitor. Worktree bytes come only from Workspace's bounded no-follow `SourceRead`. The reader walks every absolute root component from `/`, checks the opened root's creation-aware native identity against the durable reference before opening descendants, and rejects changed roots. Raw relative names reject empty/dot/parent components, repeated/trailing separators, absolute paths and NUL without Path normalization. The opened descriptor supplies Git mode from the owner execute bit (`0100`); Apple Git leaves mode 0654 as 100644. Existing source observations enter the collector only through a Workspace-minted `CurrentObservation` after exact latest-row reconciliation; raw/native hints and merely loaded rows cannot bypass that gate. The collector then enforces matching scope, path, state, complete coverage, digest, length, and its source byte cap, and never invents durable sequence/revision values. Observation reload must receive the current durable WorktreeRef: native root proof is caller-owned, not reconstructed from persisted path strings. Strict scope equality is preserved.

Each pair is copied into ASCII `left`/`right` files with mode 0600 inside an exclusively created mode-0700 directory outside the repository. The fixed command uses `git -C <scratch> diff --no-index --no-ext-diff --no-textconv --no-color --full-index --patch -- left right`, with configuration/attributes disabled and repository discovery bounded at the scratch parent. Execution retains its original authorized cwd/authority; only Git's explicit `-C` selects the private comparison directory. Exporting a private command is one-shot and marks its files potentially in use. After spawn, the runner transfers the child's non-Clone ProcessIdentity into the shared scratch guard. Only immutable CapturedProcessEvidence carrying matching actual-wait ReapedChildIdentity permits cleanup; raw fixture output and foreign child evidence cannot do so. Execution/product consumes the separate non-Clone DirectChildReap settlement token before passing evidence to Workspace. Unused intents clean on drop. Issued or bound files without confirmed matching reap are quarantined on timeout/drop, including unexpected duplicate bindings. A supervised cancellation handoff owns both the child and the same intent until bounded cancellation/reap returns matching evidence; no timeout is reported as cleanup or settlement. Exit 0 means identical and 1 means a successful difference; missing exit, exit >=2, truncated streams, or incomplete drains reject evidence.

Each attempt brackets capture with complete HEAD/index/tree/untracked/index-stat/index-path/conversion-config metadata, the native index timestamp or its proven absence, applicable attribute-file presence, and exact trusted `check-attr` output or a forced-capture marker, rereads every selected source including absence and mode, and restats skipped tracked paths. Observed instability retries the entire capture once, then returns `UnstableSnapshot`; no partial attempt becomes clean output. This establishes observed equality across a bounded window, not an atomic filesystem transaction. Fixed limits are 256 changed/untracked paths, 64 KiB aggregate changed raw path bytes, 1 MiB per blob/source/metadata/patch stream, 8 MiB aggregate retained changed-source plus distinct comparison-blob payload, with a separate 64 MiB transient source-hash ceiling, 1 MiB aggregate patches, and 64 KiB stderr. A repository may have more than 256 clean tracked paths; its complete metadata streams must still fit their independent byte ceilings. Truncated or over-ceiling Git streams report `EvidenceTooLarge`, which Assistance renders as `capacity`. Unborn HEAD, changed/Git-listed paths resolving to symlinks or special files, submodules, malformed output and unsupported object modes remain explicit errors. Git-listed untracked entries are type-checked without reading their content; no-follow nonblocking opens cannot hang on FIFOs. Git may omit untracked FIFOs/devices/sockets entirely (observed for FIFO on Apple Git), so this is an inventory of Git-listable paths, not a complete filesystem scan. Unseen non-Git entries are outside v0.1 coverage.

`RawGitEvidence` remains a bounded metadata/persistence container: constructors reject query/mode mismatch, stdout above 1 MiB, or stderr above 64 KiB even when truncation flags are false. It does not certify a complete snapshot. Rename/copy porcelain records require their second raw path, and conflict records require actual stage data before any logical record is returned. An owner-scoped bounded expansion retains the exact GitScope, capture generation, comparison identities, operation reference and first unreturned hunk; pages are contiguous prefixes so entries are neither duplicated nor omitted. Invalidated evidence is unavailable/stale and neither Workspace nor Changes reconstructs omitted patches.

`BaselineContext::new` supplies descriptive Partial/Unknown context only; it rejects Complete and reports `NotCaptured`. `DurableWorkspace::capture_baseline` requires current durable authority, at most six scoped Git records and 128 registered raw source paths, and stores at most 4 MiB of framed Git/source bytes. Exact retries fingerprint historical request facts before live authorization and return the stored capture even if files subsequently change. `committed_baseline(operation)` recovers the immutable committed result and its exact DB-owned scope after crash/restart or native root loss; no caller scope is accepted and no live authority is minted. Each source open verifies the opened root creation identity before bytes are read, and capture revalidates native identity plus the durable grant before and inside commit. Root replacement aborts capture rather than producing an unavailable-file entry. Stored captures retain a payload digest and exact worktree/incarnation/epoch, but remain `Partial` with an `Unverified` joint capture window. No atomic Git/source window is yet established, so no v0.1 caller can mint Complete. Changes preserves this window status and rejects a captured baseline from another scope.

The raw collector is exercised through real Execution admission, bounded capture and reap on Apple Git 2.50.1. Active clean/smudge/process, textconv, external-diff and fsmonitor sentinels remain untouched in head/staged/unstaged. The product dispatcher must supply its current authority, generation, runner and any applicable source observations; this contract does not claim that product hookup is complete.

Workspace contributes current, ownership-scoped bounded observations/evidence and detail expansion to `context`, `diff`, and `inspect`; Changes produces the logical `diff` result and Assistance renders every public tool response. Invalid evidence returns `unavailable`, `incomplete`, or `failed` with scope, freshness, coverage, provenance, and a bounded detail reference. `ready` means requested evidence is available, never that a product, check, or criterion is verified.

## Persistence, lifecycle, and cache gate

Workspace installs source observations and the immutable identity/authority/baseline schema through Application's accepted migration admission. Nonfresh upgrades require Application's configured private backup root. It supplies stable domain/key and trusted SQL/digest, treats `AlreadyApplied`, `Incompatible`, `OutcomeUnknown`, and `BackupUnavailable` exactly as Application reports them, and never assigns migration versions or runs a second attempt after an unknown result. After `OutcomeUnknown`, it calls only `Store::migration_admission(domain, key)` to reconcile; that lookup never replays SQL.

Registered-path reconciliation loads the exact latest same-worktree/incarnation/path observation in the insertion transaction; only the matching current authority epoch can supply the prior state. Caller-supplied previous observations are ignored. A bare rename hint does not establish native identity continuity, so v0.1 returns independent delete/create facts. A missing worktree root returns `RootUnavailable` without recording a missing descendant or emitting Close; a missing descendant beneath an opened root retains explicit missing-path semantics.

A temporary missing or moved path is not closure. Stop, reconnect, handoff, missing paths, and moves never request cache retirement. Workspace may publish a verified closure/reset fact to a later retention boundary, but does not retire any cache itself. Strict lifetime of opaque/native provider indexes at closure remains an owner decision; no weaker cache-retention claim is made here.

## v0.1 contract scenarios

- Two actors race `start` for one discovered worktree: exactly one receives authority; neither receives a second active worktree.
- A binding is stopped between validation and grant: no authority is issued; an already admitted local transaction may settle but no later authority use succeeds.
- Discovery returns a newline, leading-dash, space, or non-UTF-8 path: Workspace preserves raw bytes and either parses the exact supported encoding or reports an explicit unsupported/incomplete result.
- An observation arrives after a newer sequence, or baseline capture is partial: it is stale/incomplete rather than current/clean.

Consumer acceptance freezes this revision and its SHA-256 before code relies on it. Subsequent contract changes require bilateral revision acceptance.

## Discovery validation and Git compatibility

`git::discovery::validate_discovery(candidate_cwd, operation, outputs)` accepts exactly the three correlated `GitDiscoveryEvidence` results for `--show-toplevel`, `--path-format=absolute --git-common-dir`, and `worktree list --porcelain -z`. It requires uncancelled execution for all three results, complete bounded streams and success, exact operation/query correlation, one uniquely listed candidate, and matching candidate Git administrative identity. Both returned identity roots are the verified top-level; nested cwd is never stored as a root. Common-dir must be absolute; there is no cwd-relative fallback. The candidate's `.git` directory or linked-worktree gitdir/commondir/backpointer must identify the same canonical shared directory. Other entries are parsed boundedly and uniquely without opening unrelated stale/prunable paths. DurableWorkspace revalidates the returned native roots before allocating an incarnation.

Absolute discovery requires Git 2.31 or newer, when [`--path-format` was added](https://github.com/git/git/blob/master/Documentation/RelNotes/2.31.0.adoc). A rejected/echoed unsupported option yields `UnsupportedDiscoveryGit`; relative or malformed output fails closed. Raw collection requires Git 2.45 or newer, when the mandatory [`--no-lazy-fetch` option was added](https://github.com/git/git/blob/master/Documentation/RelNotes/2.45.0.adoc), and is validated on Apple Git 2.50.1 (Apple Git-155). Older binaries are explicitly unsupported. Discovery tests cover ordinary/nested/linked roots, relative-result rejection, malformed/duplicate/foreign/partial evidence, administrative backpointer mismatch, and raw newline/non-UTF-8 peer entries. Darwin filesystem refusal of non-UTF-8 filenames is an explicit platform limitation; byte parsing does not decode or rewrite them.

| Git capability | Minimum | Executed acceptance |
| --- | --- | --- |
| Absolute common-directory discovery | Git 2.31 | Apple Git 2.50.1: main, nested and linked worktrees |
| No-filter raw comparisons with mandatory no-lazy-fetch | Git 2.45 | Apple Git 2.50.1: head/staged/unstaged, fixtures and missing promisor blob |
| Raw non-UTF-8 paths | Unix byte API | Parser checks pass; this Darwin filesystem rejects creation |
